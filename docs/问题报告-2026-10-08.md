## 2. 已解决的问题

### 2.1 `image edit` 复刻参考图，内容语义全丢

| | |
|---|---|
| **现象** | 把 ATP工厂 作为参考图传入，输出是它的复刻（环形工厂 + 中央核心 + 八模块塔），prompt 里的「红细胞 + 速度残影 + 向左疾冲」全部丢失 |
| **加重实验** | 加了一整段「严禁复刻参考图的整体轮廓、装置结构、部件布局」的强化指令，**依然无效** |
| **根因** | `bl image edit` 的语义是**「编辑这张图」**，任何传入的图都会成为主体基底。它没有「参考生成」入口 |
| **修法** | 改走纯文生图 `--no-refs`；参考图仅用于**提炼 styleBlock**（用 vision 分析）与人工比对 |
| **状态** | ✅ 已解决（当前产线即此方案） |

> 附带发现：`wan2.7-image`（唯一宣称「多图参考生成」的模型）要求参考图 **≥240×240**，
> 而现有原画只有 200×200，被服务端直接拒绝（`resolution must be at least 240x240`）。
> 该路径需原始尺寸图才能验证。**用户已指定只用 2.1-pro，此路径暂不启用。**

### 2.2 三张构图雷同

| | |
|---|---|
| **现象** | 首轮 3 张图标全被同一个「八角金属环」模板统治 |
| **根因** | `seed` 步进为 1（1000/1001/1002）。**扩散模型的相邻 seed 倾向产出相似构图骨架** |
| **修法** | 新增 `seedStride`，改为 1000 → 1000/2000/3000… |
| **状态** | ✅ 已解决 |

### 2.3 技能语义丢失（画面无主体）

| | |
|---|---|
| **现象** | 「红细胞带速度残影向左疾冲」→ 出来一个圆形装置 + 一道光，**没有红细胞** |
| **根因** | 轴取值只写「效果词」，没有强制主体出场 |
| **修法** | 轴取值统一写成 **「主体 + 动作 + 效果」三段式**：「**一颗**红细胞**拖着**青色速度残影**向左疾冲**」 |
| **状态** | ✅ 已解决（效果立竿见影） |

### 2.4 永远有个金属外框（第一轮）

| | |
|---|---|
| **现象** | 每张图标都被一圈八角金属框包围 |
| **错误尝试** | 在负向词里加「圆形边框 / 金属外框 / 装饰边框 / 图标外框 / 环形框架 / 底托 / 底座 / 徽章」——**一条都没生效** |
| **根因** | ① **负向词只管风格属性，管不了构图**；② styleBlock 里「**图标**」+「**主体占画面 65%~85%**」构成了容器暗示 |
| **修法** | 改**正面描述**；「图标」→「图案」；「占 65~85%」→「占 60~80%，四周留白，画面边缘就是主体自身的剪影」；显式写「不设任何外框、边框、底托、底座、徽章或容器」 |
| **状态** | ✅ 已解决 |

### 2.5 外框变形为「主体的装甲外壳」

| | |
|---|---|
| **现象** | 外框不见了，但每张图的主体外面多了一圈环状装甲（01 还多出一个未要求的岩石球） |
| **根因** | styleBlock 里「**硬表面圆角几何模块**」被模型解读为「**在主体外面加一圈机械模块**」，而不是「用硬表面语言处理主体表面」 |
| **修法** | 明确作用对象：「科幻感来自对**细胞表面**的硬表面化处理……不要把细胞改造成环绕式机械结构」+「严禁在主体外部添加任何包围结构」 |
| **状态** | ✅ 已解决 |

### 2.6 主体固有色丢失（我的设计错误）

| | |
|---|---|
| **现象** | 红细胞变成**灰蓝色甜甜圈**，红色消失；另一张变成深蓝空环，认不出是红细胞 |
| **根因** | 我写的「配色：**主体结构统一用中低饱和的深蓝、灰白、钢青**」——为了统一，把主体固有色锁成了冷色 |
| **概念纠正** | **统一 ≠ 同色。** 主体固有色是**识别特征**，游戏图标尤其靠颜色做识别。统一性应来自渲染方式、描边、背景、构图语言 |
| **修法** | 配色规则改为「保留各细胞自身固有色……统一性来自渲染方式、描边与背景」 |
| **状态** | ✅ 已解决（红色立即恢复） |

### 2.7 画面堆砌未要求的元素

| | |
|---|---|
| **现象** | 只要「一颗红细胞」，画面里多出白细胞 + 3 个病毒 + 气泡；另一张多出一个巨大红环抢主体 |
| **根因** | styleBlock 里「红细胞是……白细胞是……病毒是……」的**细胞种类枚举，被模型当成了元素清单** |
| **修法** | 删除枚举（主体由轴取值指定）；styleBlock 精简至 404 字；加「画面中只出现【内容】所描述的那一个主体，不得添加任何未被要求的元素」 |
| **状态** | ✅ 已解决 |

## 3. 通用工程规律（本次最有价值的产出）

这 7 条是跨项目可复用的，比任何一张图都重要：

| # | 规律 | 证据 |
|---|---|---|
| 1 | **参考图的语义由入口决定**。`image edit` = 以图为底编辑，不是风格迁移；加「严禁复刻」也压不住 | §2.1 |
| 2 | **负向词只管风格属性，管不了构图**。排除「厚涂/写实/模糊」有效；排除「不要画框」**完全无效**。构图要求必须写成正面描述 | §2.4 |
| 3 | **styleBlock 里任何「枚举」都会被当成规则或素材清单**。列举细胞种类 → 画面堆砌；列举颜色 → 污染枚举外的主体 | §2.7 / §4-P1 |
| 4 | **统一 ≠ 同色**。主体固有色是识别特征，不能为统一牺牲 | §2.6 |
| 5 | **相邻 seed 产出雷同构图**。内容差异大的批次必须拉大 stride | §2.2 |
| 6 | **prompt 里的「容器暗示」会变成实物**：「图标」+「占 65~85%」→ 画出外框；「硬表面模块」→ 给主体套壳 | §2.4 / §2.5 |
| 7 | **元素数量需要显式约束**。「只画【内容】指定的那一个主体」这类话必须写出来，否则模型会自主丰富画面 | §2.7 |

## 4. 未解决问题

### P1（唯一未解决）配色规则是「枚举式」的，会污染枚举外的主体

**现象**：轴取值要「一颗**青色**能量球」，出来的是**红色球体 + 白壳 + 绿环**。

**根因**：§2.6 的修法用了枚举式表述——

```
配色：保留主体固有色（红细胞红、白细胞白、病毒紫或绿）
```

模型遇到枚举外的圆形主体（能量球），退回到枚举里最像的答案（红色细胞）。

**影响范围：15 条轴取值中有 6 条的主体不是细胞**

| # | 轴取值 | 非细胞主体 |
|---|---|---|
| 04 | 一面六边形能量护盾立在白细胞前方 | 护盾 |
| 05 | 一颗青色能量球，外绕两圈同心轨道光环 | 能量球 |
| 09 | 一个紫色病毒被一道斜向青色光刃斩成两半 | 光刃 |
| 11 | 一片橙色网状结构把三个紫色病毒连在一起 | 网状结构 |
| 13 | 一股金色能量流注入一颗红细胞内部 | 能量流 |
| 15 | 一个分子结构球体，由细青色键线连接而成 | 分子球体 |

**候选方案**

| | 做法 | 代价 | 评价 |
|---|---|---|---|
| A | 逐条给 6 个轴取值打补丁（如「青色能量球体（非细胞）」） | 只重跑 05 = 0.25 元 | ❌ **不推荐**。6 条都要补，且以后每加一个新技能可能再补一次，是把全局设计缺陷摊派给数据兜底 |
| B | 全局改规则：**去枚举化 + 颜色下放到轴取值** | 需验证影响半径 | ✅ **推荐**（见下） |

**方案 B 的具体设计**

styleBlock 只留规则，不留枚举：

```
配色：主体保留其自然固有色，不要为了统一而把不同主体改成同一色系——
细胞用生物色，能量、光效、结构类元素使用轴取值指定的强调色。
统一性来自渲染方式、描边与背景，而不是同色。
```

轴取值自报颜色，不让全局规则去猜：

```
一颗发光的青色能量球体，外绕两圈同心轨道光环｜主体色：青｜强调色：荧光绿
一颗红细胞拖着速度残影，向左疾冲        ｜主体色：红｜强调色：亮青
```

### P2 未知：prompt 改动的影响半径

方案 B 是**全局改动**，理论上 01~04、06 的输出都会变。但**变多少无法靠推理确定**。

**验证方法（0.25 元）**：固定 `seed=1000`（与现有 01 完全相同），用新规则重跑 01，与现有 01 逐张对比。

| 结果 | 含义 | 决策 |
|---|---|---|
| 几乎一样 | 该规则对细胞主体是中性的 | 放心全局改，01~06 无需重跑 |
| 明显不同 | prompt 敏感 | 二选一：全量重跑（3.75 元）／冻结当前批次、新规则只用于后续新增 |

**这个测试的价值远超 0.25 元**：它给出「prompt 改动的敏感度基线」，决定了以后每次调风格要付多大代价。建议**固化成一个改风格前的 A/B 流程**。

### P3 已规避：参考图路径被 edit 语义阻断

除非获取原画**原始尺寸图（≥240×240）**，否则 `wan2.7-image` 的「多图参考生成」路径无法验证。
用户已指定只用 2.1-pro，**该路径暂不启用**，当前纯文生图方案不受影响。

## 7. 附录：配置项清单

### 7.1 风格包 `styles/<name>.json`

| `negativeBlock` | 负向词（只管风格属性） | 含边框类词条（保留但已知无效） |
| `constraints` | 硬约束，进 prompt 的【硬约束】段 | 单主体 + 固有色 + 唯一高饱和色 |
| `model` | 默认模型 | `qwen-image-2.1-pro` |

| `watermark` | 水印 | `false` |
| `refsDir` | 参考图目录 | `refs/cellgame`（当前产线不用） |

### 7.2 任务 `jobs/<name>.json`

| 字段 | 作用 | 当前值 |
|---|---|---|
| `subject` | 主体描述（冻结） | 细胞题材游戏技能图案 |

### 7.5 工程约定（必须遵守）

1. **所有 `bl` 调用走 `execFile` 传数组参数，绝不经过 shell。**
   Windows 下 `shell:true` 会把带空格/中文的 prompt 拆散；git bash 会静默丢弃参数（实测）。
2. **视觉描述按内容 SHA-256 缓存**，同一张图只花一次钱。
3. **全程可 `--dry` 预演**，零成本验证参数组装。
4. **改风格块前先做 A/B**（见 §4-P2），先确认影响半径再决定是否全量重跑。
5. **不经用户同意不更换模型。**
