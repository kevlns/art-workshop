# 模型与执行架构

模型扩展不修改任务调度和界面判断。未知型号、未知协议、无效响应都明确失败；提交结果未知时禁止重复提交。

| 模块 | 职责 |
| --- | --- |
| `lib/model-catalog.mjs` | 模型型号、输入输出能力、参数规则、尺寸、协议操作和展示说明 |
| `lib/model-registry.mjs` | 启动时验证并索引定义；提供执行契约及统一资格判断 |
| `lib/generation-policy.mjs` | 校验、规范化请求、记录参数转换、冻结和复核执行契约 |
| `lib/adapters/` | 协议登记、准备输入、序列化、提交、查询、响应解析 |
| `lib/execution/remote.mjs` | 持久化回执后轮询、取消等待、恢复原任务、下载原结果 |
| `lib/transport/` | 有界 HTTP/JSON 与 CLI 子进程，不承载模型判断 |

界面与配置保存共用 `modelEligibility`。接口类型列表由适配器注册表提供；模型发现只补齐准确型号的声明能力，不推定账号权限或自动启用。

## 扩展规则

同协议新模型增加完整模型定义与契约测试。字段规则描述类型、默认值、范围或枚举及协议字段名；参数不再受全局固定白名单限制。模型声明在启动时检查重复标识、必要限制和协议字段。

新协议实现 `prepare / submit / query`，通过 `createAdapterRegistry` 登记。同步提交返回完成结果；异步提交返回上游任务身份。界面、任务运行时不包含型号名称分支。输入文件限制由模型声明提供。

`art/model-contract-v1` 排除型号别名列表、展示说明、来源链接及 CLI 示例字段；这些文案变化不改变执行哈希。`art/image-request-v1` 保存规范化请求，`art/execution-contract-v1` 冻结逐项契约。请求参数、尺寸、转换策略或协议规则变化必须重新预演。没有当前执行契约的旧预案不能启动。

## 生命周期

每个计划项分别保存 `remoteExecutions[inputHash]`，包括 schema=art/remote-receipt-v1、请求哈希、适配器及版本、服务地址、提交时间、上游任务 ID 和结果。回执不保存 API Key。

1. `prepare` 先检查凭据与输入，不发起生成。
2. 持久化 `dispatching` 后才能 POST。
3. 持久化 `accepted + taskId` 后才能查询。
4. 持久化 `completed + urls` 后才能下载。
5. 下载采用临时文件和排他发布，不覆盖已有不同内容的产物。

提交中断而无任务 ID 的运行保持未知，不能重发。取消等待不等于上游取消；适配器没有停止能力时保留任务身份和占用。

```sh
v-cli art task resume TASK
```

`task resume` 仅恢复原上游任务查询或原结果下载，不调用提交接口，也不补发尚未提交的项目。已有成功产物跳过；参数及请求身份不同、原工作进程仍活着、原提交结果未知均拒绝恢复。恢复沿用 taskId、manifest 和每项输入哈希。

上游已完成而本地下载失败时，恢复原运行取回结果，不能通过失败项重试再次付费生成。原运行查询入口 `task recover --operation` 仍只查登记，不隐式启动工作进程。

Vant 通过 `ART_IMAGE_CONNECTION` 和 `ART_IMAGE_KEY` 注入连接，不绑定厂商命名。单独使用 DashScope 时，适配器通过固定版本的百炼核心库读取既有 API Key 配置；明确注入连接后不回退到其他凭据或站点。

## 验证边界

单元与协议模拟验证声明扩展、统一筛选、严格响应和回执顺序；真实子进程测试验证工作进程丢失及取消后恢复，统计生成 POST 次数不增加。上述验证不等同于付费模型真实出图或已安装版本更新。

新模型至少覆盖合法请求、参数边界、模式和输入拒绝；新协议还需覆盖提交结果未知、持久化失败、按原身份恢复、取消及下载失败。HTTP 响应体、下载大小和时间有界；认证请求禁止重定向，下载不携带模型密钥。当前查询异常保留身份并停止等待，不自动重试查询或提交。
