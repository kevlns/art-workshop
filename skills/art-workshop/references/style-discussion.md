# 参考图风格讨论与回填

用户说“看看这张图的风格，帮我填进去”时，先沿用当前风格对象与会话引用；没有对象且用户要求保存时才创建草稿。先读当前对象、revision 和宿主返回的讨论契约，不让用户重复提供已知信息。当前消息指定的图片和用途优先，不将历史图片全部作为参考。

导入会话附件时，source 原样使用宿主提供的项目相对 path；该 path 可能已经是没有扩展名的哈希文件，不在后面拼附件名称，也不改用应用仓库路径。无法读取时先核对本条附件资料，不全盘搜索其他项目来猜来源。

## 从图像观察到草稿

读取真实图片像素，再分析可复用的媒介观感、线条、笔触、明暗处理、刻画密度及色彩关系。某张图里的具体人物、比例、部件、身份色、材质、场景和光源记录在相关观察上下文，不写成跨主体风格要求。没有证据的分类可以不填，不补齐一套看似完整的规则。

宿主模型能直接看图时，可以根据当前图像观察整理风格草稿；这不等于已经执行了正式风格分析任务。宿主无法看图时使用当前对象配置的视觉分析能力，能力未配置或不可用就说明限制，不凭图片名称猜测。只为普通措辞修改不重复分析。

用户已授权分析和填写时，把贴合目标的分析与适度专业化描述自动保存到当前草稿，保留未修改配置，使用工具提供的 description、constraints、rules、analysis 等实际字段。图像观察通常适合写成 default 倾向；required/avoid 用于确实需要必须遵守或避免的要求，注意不要仅因参考图如此就升级强度。既有身份、分析模型、参考分类及无关规则保持不变。

描述可以有细节，重点是保持适用范围和弹性。例如由柔和光晕提炼出柔和高光是合理的，直接变成所有资产禁止硬边高光就可能过度。毛发、雪面等可作观察例子，通用规则尽量提炼其背后的笔触或过渡方式。配色可描述参考图中的颜色及关系，但不要无意中固定以后所有主体的身份色。无需机械删除具体颜色、数量或形容词，按它们是否有依据、是否帮助当前目标来判断，也不要求填满所有绘制主题。

rules 使用当前工具返回的规则数组，不把主题目录包装成新对象。没有正式分析报告的草稿使用对象更新；已有可沿用的正式报告与参考证据时才使用规则修订入口，不先试一个会报错的入口再换另一个。

用户后续说“线条稍利落一点，颜色别变”时，只局部调整相关规则的措辞与程度，保留其他规则和配置，不把小幅修改改成全局禁用软边、纹理或其他技法。原意已清楚就直接保存，不以分类未填满为由继续追问。

## 正式报告与实际保存

需要运行正式分析任务时，按 [项目管线](project.md) 和当前工具契约执行，沿用原 taskId 查询或恢复，不通过新建分析绕过失败。区分三份内容：图像观察是证据；报告 recommendation.rules 是分析建议；对象 config.rules 才是实际保存的草稿规则。正式风格核心另由采用操作生成。

不能只展示报告建议就声称已回填。用户要求填写配置时，分析完成后还需按真实契约保存可用规则；已有未变参考证据的规则修订用对应 revise 入口，其他情况按工具允许的更新入口处理。真实未决问题保留对应项，不清空问题或更改参考来强行通过，也不自动采用或冻结。

用保存回执中的完整对象核对 revision 及实际 config；回执缺少完整内容时再读取一次。简短展示实际填入内容与必要未决项；用户要看最终配置时直接展示保存后的 JSON，不展示另写的一份理想配置。不逐条解释自己没有做哪些扩写，也不附带与本轮无关的下一步确认。保存失败、分析尚未完成或仅有观察建议时如实说明，不声称已经生效。一次校验后结束，本轮不自发循环分析、改写或出图。
