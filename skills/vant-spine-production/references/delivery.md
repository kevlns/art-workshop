# 导出与运行验收

## 目标端与交付物

核对项目实际使用的 Spine Runtime 主次版本、加载格式、材质和透明度约定，再选对应导出设置。制作源保留分层母版、定位信息、可编辑骨架及附件原图；运行目录仅放加载器消费的骨架、atlas、图集和项目要求的索引或集成资源。GIF、过程图和重复的原尺寸部件留在源资产或预览目录。

Vanter 的实例交付 Spine 4.2 骨架 JSON、原始部件 PNG、PMA 图集、动作索引及 Unity 包。编辑时在匹配版本的 Spine Editor 导入 JSON 并关联原图，可再保存为原生 `.spine` 工程。交付说明要准确写出实际文件格式。

交付前按[命名与索引](rig-motion.md#命名与索引)核对完整动作清单。接入 Vanter 时，按实际入口验证入场、循环、表情衔接和退场完成。

## 保真与开销

| 现象或指标 | 如何取舍 |
| --- | --- |
| 原图清楚，放到界面就糊 | 用最终显示大小和设备像素比确定所需纹理分辨率；对照图集原像素、运行时渲染缓冲和界面缩放，找出第一次变糊的位置，再决定改导出比例或渲染设置。 |
| 包大或显存高 | 分开记录下载字节数与解码后的纹理开销。盘点图集页数、长宽、透明空白和重复图块。先修剪、合理打包和复用，再试缩小大图；为边缘滤波留足间距。每次在最大实际尺寸复看眼睛、细线和半透明边。 |
| 动作复杂时掉帧 | 用同一设备、镜头、角色数量和最重的动作比较帧耗时。检查实际 draw calls、材质或混合切换、大面积半透明叠画，以及每帧变形的顶点和骨骼影响数。优先优化测到的瓶颈，保住轮廓和关键姿势。 |
| 出现黑边、白边或图块串色 | 在深浅底色和运动中检查。核对导出与加载端的直通或预乘 Alpha、纹理过滤和 atlas 边缘填充，再调整压缩。 |

记录调整前后的运行包大小、纹理尺寸与页数、目标端测量值，并保留同帧同尺寸的图。交付时从干净目录用实际加载入口播放一次，检查 atlas 各页和附件都能解析、大小写路径匹配、动作完成事件与循环正常。仅验证过 Unity 时，将 Web 验收标为待测，反之亦然。[Spine 性能指标](https://esotericsoftware.com/spine-metrics) · [Spine 图集打包](https://esotericsoftware.com/spine-texture-packer)

## 工具入口

以 `v-cli art spine describe` 读取当前工具契约。各制作命令接受 `--workspace <工程目录> --input <工程内配方.json>`，产物写入配方指定的新目录。以已有产物为输入继续修订。

| 当前工作 | 入口与产物 |
| --- | --- |
| 原型与补绘 | 使用当前工作环境的生图、编辑工具制作原型和补绘图。用 `spine parts` 指定母版像素矩形、轴心、前后顺序与遮挡关系。蒙版接受透明度或灰度图；同比例高清替换图按原矩形配准，图集保留替换图像素尺寸。检查 assembled.png，采用补绘前后对照 patched.png 与原图。 |
| 骨架与动画 | `spine build` 读取 parts.json，按轴心建立初始绑定。用 bones 按名增改骨骼，meshes 指定目标插槽、UV、三角索引、各点的骨名/骨局部坐标/权重。animations 使用 Spine 4.2 时间线。后续可传已编辑的 rig 骨架 JSON，保留其余皮肤、约束和动作。 |
| 制作验收 | 美术工坊 → Spine 接入导出骨架。桌面对话可用 `vant_spine_preview` 打开同一资产。需要留存指定姿势或分享时，用 `spine capture` 选择动作、秒数或均匀帧数，输出逐帧 PNG、对照图及可选 GIF；需要本机 Chrome、Edge 或 Chromium。 |
| 交付 | 核对导出的骨架、图集 PNG 与 atlas、animations.json 和 report.json。report 给出运行文件字节数、未压缩 RGBA 占用、骨骼、顶点和影响数。目标引擎的真实帧耗时需在该引擎测量。 |
